# 投标文件目录构建规范

投标文件目录**没有法定统一结构**。本文件是目录问题的**唯一规范**：SKILL.md 与其他 references 均引用本文件，不另行规定目录规则。

## 一、目录来源铁律

```
招标文件（含补遗/澄清）是否给出"投标文件组成 / 投标文件格式"？
├─ 有 → 模式 A：逐字照抄招标目录（第二章）
└─ 无 → 模式 B：根据用户提供的采购内容推导目录 + 用户确认（第四章）
        └─ standard-structure.md / templates.md / 任何示例
           ——只是章节素材库与文书模板，一律不得直接当作目录使用
```

**模式 A 三不原则**：不增章节、不减章节、不调顺序；章节标题（含编号与措辞）**逐字保留**。

---

## 二、模式 A：招标目录提取与照抄流程

### 2.1 定位目录条款

招标文件中目录规定的常见位置（以下**全部检查**，缺一不可）：

1. **"投标文件格式"章节**（最常见，通常为最后一章）——给出各文书模板，模板集合即标书目录
2. 投标人须知**前附表**——"投标文件组成"清单
3. 投标人须知正文——"投标文件的编制"节
4. **评标办法**——否决条款常隐含组成要求（如"未按规定格式填写×× 作无效标处理"）
5. **补遗/澄清文件**对上述内容的修改——后发优先

### 2.2 摘录

- 逐字摘录章节清单：编号、标题、装订顺序、正副本要求
- 格式章节给的是**文书模板集合**而非目录清单时：每个模板对应标书中的一章/一节，**按模板在招标文件中出现的顺序**组装目录
- 同步记录装订性要求：哪些章节要求"加盖公章""单独密封""正本放入第 X 袋""单独装订成册"

### 2.3 冲突处理

| 冲突情形 | 处理 |
|---------|------|
| 原招标文件 vs 补遗 | **补遗优先** |
| 前附表 vs 正文格式章节 | 不臆断，列出差异**询问用户**（建议向招标代理书面澄清） |
| 招标格式章节 vs 评标打分所需材料 | 打分所需材料并入**最接近的既有章节**，不得新开一级章节 |

### 2.4 目录合规比对表（必输出）

目录确定后、动笔编写前，必须向用户输出比对表：

| 序号 | 招标格式规定章节/文书 | 投标文件目录章节 | 一致性 | 备注 |
|------|---------------------|-----------------|--------|------|
| 1 | 第六章 格式一 投标函 | 一、投标函 | 一致 | 需签字盖章 |
| 2 | 第六章 格式二 法定代表人授权委托书 | 二、法定代表人授权委托书 | 一致 | 附双方身份证复印件 |
| … | | | | |

**一致性判定**：逐条比对后，多一章、少一章、顺序不符、标题措辞或编号改动，均判不合格，修正后重新比对，直至全部"一致"。

### 2.5 部分给定的混合处理

招标文件只给出部分格式（如仅有投标函和报价表模板，无技术标格式）：

- 已给部分照抄（模式 A 规则）
- 缺失部分按第四章推导生成，目录中标注"**（招标未规定，按行业惯例编制）**"
- 向用户明确说明哪些章节来自招标规定、哪些为推导补充

## 三、模式 A 目录红线（违反即风险）

- ❌ 增加招标文件未要求的章节（画蛇添足，暴露弱点，甚至被认定附条件投标）
- ❌ 擅自合并或拆分招标规定的章节
- ❌ 改动标题措辞与编号（评标专家按招标目录逐项找内容，改了等于丢分）
- ❌ 遗漏格式章节中的任何文书（哪怕看似次要，如中小企业声明函、保密承诺函）

---

## 四、模式 B：内容推导流程（无招标目录规定时）

**不套用任何固定目录模板**。按以下步骤从用户提供的项目内容推导：

### 4.1 输入

- 项目名称与采购内容描述（必须，缺失则先询问用户）
- 行业画像判定结果（[industry-profiles.md](industry-profiles.md) 的决策树）
- 用户资料状况（`bid-data/profile.md` 已有哪些资质、业绩、人员）
- 已知评分规则（如有；用户可能了解大致权重）

### 4.2 推导步骤

1. **定骨架**：三标框架（商务标 / 技术标 / 报价标）作为一级划分；单册或分册按项目规模与用户要求定
2. **选要素**：从 [standard-structure.md](standard-structure.md) 章节要素库按画像选取必选章节
3. **按画像定制章节侧重**：
   - IT/信息化：技术标加重架构、功能、数据、安全（等保）、实施、运维
   - 工程建设：技术标以施工组织设计为核心，含进度、安全质量、项目班子
   - 货物采购：技术参数响应表为核心，含配置清单、供货运输、安装调试、质保
   - 服务类：服务方案、SLA 量化、人员配置、应急预案
4. **按资料定深度**：资料齐 → 章节写实并引用 profile.md 事实；资料缺 → 章节保留、内容用占位符。**不得因资料缺失删掉行业必备章节**
5. **按评分定权重**（已知评分规则时）：高分值章节前置、写厚写透；低分值章节合并简化

### 4.3 输出目录方案（必经用户确认）

| 章节 | 所属分册 | 选择理由 | 素材来源 | 预计篇幅 |
|------|---------|---------|---------|---------|
| 一、投标函 | 商务标 | 行业必备文书 | templates.md + profile.md | 1 页 |
| 二、总体技术方案 | 技术标 | IT 画像核心章节，采购内容为平台建设 | 生成 + 【待补充】 | 15~25 页 |
| … | | | | |

**用户确认目录后才生成正文**；用户调整意见直接修改目录后重新确认，确认记录在交付说明中。

### 4.4 输出声明

文件开头注明："本投标文件按行业通用标准编制，具体章节、格式、装订要求以最终招标文件为准。"

---

## 五、目录自身编排规范

- 目录展示到三级标题，编号体系与正文一致（见 [format-spec.md](format-spec.md) 第五章）
- Word 交付：用 TOC 域自动生成（pandoc `--toc`），禁止手工页码
- 正文增删章节时**目录同步更新**，纳入自检清单
- 招标要求的"目录格式"（如逐页目录、指定级数）从其规定

---

## 六、目录自检清单

- [ ] 模式 A：目录与招标"投标文件组成/格式"**逐条比对一致**，比对表已输出
- [ ] 模式 A：补遗对目录/格式的修改已纳入
- [ ] 模式 A：格式章节全部文书均已入目录；无增、无删、无重排、标题未改
- [ ] 模式 B：目录由采购内容推导生成，**已经用户确认**
- [ ] 混合模式：推导补充部分已标注"按行业惯例编制"
- [ ] 目录与正文章节标题逐字一致
- [ ] 装订性要求（单独密封、正副本、签章页）已随目录记录并传递到输出
