# 项目资料目录规则（bid-data/）

本技能是 **Paperclip 公司级技能**，会被安装到不同公司的 agent 环境。因此**不在 skill 内存放任何公司资料**——所有资料放在**当前投标项目的目录**中，AI 运行时按本规则从项目目录读取。

> 一句话规则：**AI 在项目根目录找 `bid-data/`，读 `bid-data/profile.md` 拿结构化信息，按其中的相对路径引用扫描件；招标文件放 `bid-data/tender/`；生成的标书输出到 `bid-data/output/`。**

---

## 一、项目目录结构

每个投标项目（公司文件空间中的一个文件夹）按以下结构组织：

```
<项目根目录>/
└── bid-data/                          # 投标资料目录（本技能的固定入口，必须叫这个名字）
    ├── profile.md                     # 【核心·必须】资料索引：公司信息/资质/人员/业绩/财务
    │                                  #   —— AI 的唯一结构化信息源，按 profile.template.md 填写
    ├── tender/                        # 【招标文件】本项目招标文件及澄清文件
    │   ├── 招标文件.pdf               #   有文件 → AI 自动进入"招标驱动模式"
    │   ├── 补遗书-01.pdf              #   澄清/补遗/答疑，按时间顺序放
    │   └── 工程量清单.xlsx            #   附件（图纸/清单/格式模板等）
    ├── company/                       # 【公司固定资料】扫描件/PDF，从公司资料库整体拷入
    │   ├── 01-公司概况/               #   公司简介.md、营业执照副本.pdf、开户许可、组织架构
    │   ├── 02-资质证书/               #   ISO 体系、行业资质、软著/专利、高新证书（一证一文件）
    │   ├── 03-财务资料/               #   近三年审计报告/、银行资信、纳税证明、社保证明
    │   ├── 04-人员资料/               #   每人一个子目录：身份证/注册证书/职称/社保/简历
    │   │   └── 张三/
    │   ├── 05-业绩合同/               #   业绩合同扫描件（与 profile.md 业绩表逐条对应）
    │   ├── 06-信誉声明/               #   信用中国截图、无违法声明、裁判文书网查询截图
    │   ├── 07-常用文书/               #   公司标准封面、常用承诺函等自有模板
    │   └── 08-签章素材/               #   公章/法人章/签字 透明底PNG（电子标用，敏感）
    └── output/                        # 【输出目录】AI 生成的投标文件写到这里（AI 创建）
        └── <项目名>-投标文件/
            ├── 00-封面与目录.md
            ├── 01-商务标.md
            ├── 02-技术标.md
            ├── 03-报价标.md
            └── 待补充材料清单.md
```

### 最小可用集

只有 `profile.md` 是必须的。**最小可用** = 项目根建 `bid-data/`，放入填好的 `profile.md`；扫描件目录按需添加，没有的目录不建。招标文件有则放 `tender/`，没有就走标准兜底模式。

## 二、profile.md —— 唯一结构化信息源

### 设计原则

- **结构化信息全部集中在 profile.md**：公司名称、信用代码、资质编号、人员证书、业绩金额等 AI 直接填入标书的内容，全部以 Markdown 表格写在 profile.md，**不需要 AI 解析扫描件来提取**
- **扫描件只按路径引用**：`company/` 下的 PDF/图片是"装订材料"，AI 在标书中引用其相对路径作为插入占位，不解析内容
- **一处更新，处处生效**：资料变化只改 profile.md + 替换对应文件

### 填写规则

1. 按模板（[profile.template.md](profile.template.md)）的表结构填写，**表头不改**，AI 按表头定位字段
2. 文件路径填**相对 `bid-data/` 的路径**，如 `company/02-资质证书/ISO9001.pdf`
3. 证书有效期格式 `YYYY-MM-DD`，AI 生成时会自动检查临期（90 天内）并提醒
4. 没有的资料：表格行留空或删掉该行，**不要编造**
5. 多个投标主体：一个项目一个 `bid-data/`；不同主体在不同项目目录下各自的 `bid-data/` 中维护

### 引用优先级

AI 生成标书时按以下优先级取数：

```
1. bid-data/tender/ 中的招标文件      —— 最高：招标要求永远优先
2. bid-data/profile.md               —— 公司/项目事实信息
3. 本 skill references/ 的行业规范与模板 —— 结构、写法、兜底格式
4. 占位符【待补充：xxx】              —— 以上都没有时，绝不杜撰
```

## 三、AI 工作流（按目录规则）

### 第 0 步：扫描项目目录

```
检查 ./bid-data/ 是否存在
├─ 不存在 →
│    ① 向用户说明目录规则（本文件）
│    ② 询问：是否有招标文件要上传？
│    ③ 按模板初始化 bid-data/profile.md 骨架（空表）
│    ④ 用户不想等资料齐 → 直接用占位符模式生成标书，文末输出"待补充材料清单"
├─ 存在，有 profile.md，tender/ 有招标文件 → 招标驱动模式（模式 A）
├─ 存在，有 profile.md，tender/ 无文件 → 询问用户（可提供）或标准兜底模式（模式 B）
└─ 存在，无 profile.md → 提示用户按模板补 profile.md；或扫描 company/ 目录
     尝试从文件名推断（下策，须与用户确认后才能写入标书）
```

### 引用与输出

- 结构化信息（公司名、资质、人员、业绩）→ 从 profile.md 直接填入对应章节
- 装订材料（执照、证书、合同复印件）→ 标书中写 `【待插入：营业执照副本复印件（bid-data/company/01-公司概况/营业执照副本.pdf）】`
- 签章位置 → 纸质标标注 `（加盖投标人鲜章）`；电子标另注 `（签章素材：bid-data/company/08-签章素材/公章.png）`
- 生成的标书一律写入 `bid-data/output/<项目名>-投标文件/`，不写到其他位置

### 资料维护约定

- **skill 对 `bid-data/` 只读引用 + 仅创建 `output/`**：不修改、不删除用户资料
- `profile.md` 由用户（或 AI 按用户口述代填）维护
- 资质证书、审计报告临期（90 天）或过期 → 生成时在交付说明中提醒
- `08-签章素材/` 为敏感目录：AI 仅在用户明确要求做电子签章版时引用，不复制到 output/ 之外
