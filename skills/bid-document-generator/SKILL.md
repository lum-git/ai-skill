# 投标文件生成器

根据项目目录中的资料和用户提供的信息，生成结构完整、应答规范、可直接编辑使用的投标文件（标书）。支持两种工作模式：**有招标文件**（以招标文件要求为准绳，逐条应答）和**无招标文件**（按行业通用标准结构生成）。

本技能为 Paperclip 公司级技能，**不在 skill 内存放任何公司资料**——公司资料、招标文件均放在**当前投标项目目录**的 `bid-data/` 下，按固定目录规则读取（见 [第六章](#六项目资料目录规则bid-data) 和 [references/data-layout.md](references/data-layout.md)）。

---

## 核心能力

1. **招标文件驱动生成**：解析招标文件（PDF/Word/文本/图片），提取项目信息、资格要求、技术要求、商务要求、评分标准、格式要求、否决项，建立"招标要求 → 投标应答"合规矩阵，逐条点对点应答。
2. **无招标文件兜底生成**：按行业通用标准结构生成完整标书，行业画像见 [references/industry-profiles.md](references/industry-profiles.md)。
3. **项目资料自动引用**：读取项目 `bid-data/profile.md` 中的公司信息、资质、人员、业绩，直接填入标书；扫描件按路径引用为插入占位（见 [references/data-layout.md](references/data-layout.md)）。
4. **三标分离**：商务标、技术标、报价标分册组织，可独立成册或合并装订。
5. **关键文书模板**：内置投标函、法定代表人身份证明、授权委托书、投标保证金承诺、资格证明文件清单、商务偏离表、技术偏离表、报价汇总表等高频文书模板（见 [references/templates.md](references/templates.md)）；公司自有模板（`bid-data/company/07-常用文书/`）优先于内置模板。
6. **合规自检**：生成后对照否决项（废标条款）、实质性要求逐条自检，输出检查清单。

## 二、工作模式判定（第 0 步）

接到请求后，**先扫描项目目录，再判断工作模式**：

### 2.1 扫描 `./bid-data/`

| 扫描结果 | 模式 | 动作 |
|---------|------|------|
| `bid-data/tender/` 有招标文件 | **A. 招标驱动模式** | 以招标文件要求为唯一准绳，逐条应答 |
| `bid-data/` 存在但 `tender/` 为空，用户也暂不提供 | **B. 标准兜底模式** | 按 [standard-structure.md](references/standard-structure.md) + 行业画像生成 |
| 用户只给了部分招标文件（如只有技术要求，无商务格式） | **混合模式** | 已提供部分严格按招标；缺失部分用标准结构兜底，并明确标注"未提供招标要求，按行业惯例编制" |
| `bid-data/` 不存在 | **初始化** | 向用户说明目录规则（[data-layout.md](references/data-layout.md)），拷贝 [profile.template.md](references/profile.template.md) 生成 `bid-data/profile.md` 空骨架供用户填写；用户不想等资料齐 → 直接占位符模式生成 |

### 2.2 读取资料索引

`bid-data/profile.md` 存在则**必须先读**：公司名称、信用代码、资质、人员、业绩、本项目信息（第九节）直接决定标书中的事实内容。不存在时按上表"初始化"处理。

### 2.3 主动询问缺失信息

模式判定后，向用户确认扫描/询问未覆盖的必填项：采购单位、投标主体、投标日期、联合体情况等（profile.md 第九节有则直接用）。**不要假设用户一定有招标文件**。

## 三、模式 A：招标驱动模式工作流

### 第 1 步：读取并解析招标文件

支持的输入：PDF、Word（.doc/.docx）、Markdown、纯文本、图片（OCR）。来源优先级：**`bid-data/tender/` 目录**（含招标文件、补遗/澄清、工程量清单、格式模板附件）> 用户附件/粘贴。补遗文件按时间顺序全部纳入解析，后发的补遗优先于原文件。

按 [references/tender-analysis.md](references/tender-analysis.md) 的「信息提取清单」逐项提取，至少覆盖：

- **项目基础信息**：项目名称、项目编号、采购人/招标人、采购代理机构、预算金额、最高限价、投标截止时间、开标时间地点、投标有效期、是否接受联合体
- **资格要求**：营业执照、资质证书、财务要求、业绩要求、人员要求、信誉要求（信用中国/无重大违法记录）、是否专门面向中小企业
- **实质性要求（★/▲/加粗/强制条款）**：带标记的条款通常为不可偏离项，必须逐条满足
- **否决项（废标条款）**：无效投标情形清单
- **商务要求**：交货期/工期/服务期、付款方式、质保期、验收标准、履约保证金
- **技术要求**：功能/性能指标、参数表、技术规格、实施范围
- **评分标准**：价格分、技术分、商务分的权重与评分细则
- **格式与装订要求**：正本/副本份数、电子版要求、签字盖章位置、封装要求、目录/页码要求

> 解析完成后，向用户输出一份「招标文件关键信息摘要」供确认，再开始编写。发现歧义、缺失或矛盾时，**标注出来询问用户**，不要臆造。

### 第 2 步：建立合规矩阵（应答对照表）

对每一条实质性要求和技术参数，建立三列对照表：

| 序号 | 招标文件要求 | 投标应答 | 偏离情况 |
|------|-------------|---------|---------|
| 1 | （原文摘录） | （满足/具体方案） | 无偏离/正偏离/负偏离 |

- **负偏离必须显式说明**并给出替代方案；如无法满足，提示用户可能导致废标或扣分
- **正偏离**（优于招标要求）要主动写明，作为加分项
- 该矩阵直接演化为正文中的「商务偏离表」「技术偏离表」
- 详细规则见 [tender-analysis.md](references/tender-analysis.md)

### 第 3 步：确定标书目录

**严格以招标文件规定的目录/格式为准**。招标文件通常会给出"投标文件组成"或"投标文件格式"章节，必须按其顺序、标题、编号组织。

- 若招标文件给出了格式模板，**逐字保留其标题结构**，在其要求的位置填入内容
- 若招标文件只给了组成要求未给固定格式，参照 [standard-structure.md](references/standard-structure.md) 组织，并把招标要求的必备材料全部纳入
- 招标文件**没有要求的章节，不要擅自增加**（避免画蛇添足甚至暴露弱点）

### 第 4 步：分章节编写

按目录逐章生成。每个章节：

1. 先复述/引用对应招标要求（点对点应答的核心）
2. 给出投标方的应答内容
3. 提供支撑材料清单（需要用户后补的资质、证书、业绩等用占位符标注）

关键文书直接套用 [references/templates.md](references/templates.md) 中的模板。

### 第 5 步：报价部分

报价部分必须与招标文件的报价表格式一致：

- 有报价表模板 → 严格按模板列项
- 无模板 → 用 [templates.md](references/templates.md) 的报价汇总表/分项报价表
- **数字核对**：大写金额、小写金额、分项合计、总价必须一致
- 提醒用户：最终报价需由投标方根据成本核算后填入，AI 只提供结构与计算关系，不杜撰具体金额

### 第 6 步：合规自检

按 [references/writing-guidelines.md](references/writing-guidelines.md) 的「自检清单」逐项检查，重点：

- 所有 ★/▲/实质性条款均已应答且为"满足"
- 无负偏离未说明（或负偏离已提示风险）
- 资格证明文件清单中的材料均已安排占位
- 投标函/授权书等签字盖章处已标注
- 报价大小写一致、计算正确
- 投标有效期、交货期/工期等关键承诺与招标要求一致
- 目录与正文章节标题、页码一致
- 无招标方名称、项目编号、日期等关键信息遗漏

自检结果以清单形式输出给用户。

## 四、模式 B：标准兜底模式工作流

当用户没有招标文件时：

### 第 1 步：收集最少必要信息

**先读 `bid-data/profile.md`**：公司名称、资质、人员、业绩、本项目信息（第九节）能直接用的直接用；缺失项再向用户询问（能给多少给多少，剩余用占位符）：

- 项目名称
- 采购单位 / 招标人名称
- 投标单位（投标人）名称
- 行业类别（用于选择行业画像）
- 项目简要需求 / 建设内容 / 采购内容
- 投标日期

### 第 2 步：选择行业画像

根据项目内容，从 [references/industry-profiles.md](references/industry-profiles.md) 选择对应画像，确定章节侧重：

- **IT/信息化类**（软件开发、系统集成、信息化平台）：技术方案占比大，强调架构、功能、实施、运维
- **工程建设类**（土建、安装、市政、装饰）：施工组织设计、项目经理班子、安全/质量/工期
- **货物采购类**（设备、材料、产品）：技术参数响应表、生产制造、供货运输、安装调试、质保
- **服务类**（运维、咨询、物业、物流、培训）：服务方案、人员配置、服务流程、质量保障
- 其他行业按通用结构

### 第 3 步：按标准结构生成

按 [references/standard-structure.md](references/standard-structure.md) 的三标分册结构生成：

- **商务标**：投标函、法定代表人/授权书、投标保证金、资格证明文件、商务条款响应/偏离表、公司概况、业绩、人员
- **技术标**：需求理解、技术方案/实施方案、项目组织、进度计划、质量保障、安全/环保、培训、售后服务/运维、技术偏离表
- **报价标**：投标报价汇总表、分项报价表、报价说明

> 无招标文件时，所有"响应"均按**完全响应行业惯例**编制，并在文件开头注明"本投标文件按行业通用标准编制，具体条款以最终招标文件为准"，避免用户误以为可直接提交。

### 第 4 步：自检

使用 [writing-guidelines.md](references/writing-guidelines.md) 的通用自检清单（无招标条款可对照时，重点检查结构完整性、占位符、签字盖章、报价一致性）。

## 五、输出格式与文件组织

### 5.1 输出格式

- 默认输出 **Markdown**（`.md`），结构清晰、便于编辑
- 用户需要 Word 时，用 pandoc 转换：
  ```bash
  pandoc 投标文件.md -o 投标文件.docx --toc --toc-depth=3
  ```
- 若招标文件给出了固定 Word 模板，按模板章节顺序组织 Markdown，再由用户粘贴回模板

### 5.2 文件组织与输出位置

- 所有生成产物**统一写入项目目录的 `bid-data/output/`**，不写到其他位置：
  ```
  bid-data/output/<项目名>-投标文件/
  ├── 00-封面与目录.md
  ├── 01-商务标.md
  ├── 02-技术标.md
  ├── 03-报价标.md
  └── 待补充材料清单.md
  ```
- 也可按用户要求合并为单个文件
- 配套材料（资质、业绩等）在文中以 `【待插入：xxx（bid-data/company/.../xxx.pdf）】` 占位，并在文末汇总「待补充材料清单」

### 5.3 占位符规则

需要用户填写或后补的内容，统一使用中文方括号占位符，便于检索：

- `【投标单位名称】`、`【采购单位名称】`
- `【项目编号】`、`【投标日期：YYYY年MM月DD日】`
- `【待插入：营业执照副本复印件（bid-data/company/01-公司概况/营业执照副本.pdf）】` —— 项目资料目录中**已有文件**时用，带路径方便定位
- `【待补充：项目经理注册建造师证书】` —— 项目资料目录中**没有对应文件**时用
- `【报价金额（大写）】`、`【报价金额（小写）】`
- 占位符不得写成 `xxx`、`TODO`、`待填` 等不可检索的形式

## 六、项目资料目录规则（bid-data/）

本技能是 Paperclip 公司级技能，会被安装到不同公司的 agent 环境，因此**skill 目录内只有规范和模板，不存放任何公司资料**。所有资料放在**当前投标项目根目录**的 `bid-data/` 中，AI 按固定规则读取。完整规则见 [references/data-layout.md](references/data-layout.md)，本节为执行要点。

### 6.1 目录规则速查

```
<项目根目录>/bid-data/                # 固定入口，目录名不可变
├── profile.md                       # 【必须·唯一信息源】结构化资料索引（按 profile.template.md 填写）
├── tender/                          # 招标文件 + 补遗澄清 + 清单/图纸/格式附件（有文件即模式 A）
├── company/                         # 公司固定资料扫描件
│   ├── 01-公司概况/  02-资质证书/  03-财务资料/  04-人员资料/
│   ├── 05-业绩合同/  06-信誉声明/  07-常用文书/  08-签章素材/
└── output/                          # AI 生成标书的输出目录（AI 创建维护）
```

### 6.2 引用规则

| 信息类型 | 来源 | 用法 |
|---------|------|------|
| 公司信息、资质、人员、业绩、财务（结构化） | `bid-data/profile.md` | 直接填入标书对应章节 |
| 营业执照/证书/合同等复印件（装订材料） | `company/` 下的文件 | `【待插入：xxx复印件（bid-data/company/.../xxx.pdf）】` |
| 公司自有文书模板 | `company/07-常用文书/` | 优先于 skill 内置 templates.md |
| 签章 | `company/08-签章素材/` | 电子标注章位 + 素材路径；纸质标注"加盖鲜章" |
| 招标文件 | `tender/` | 自动发现并解析（含补遗，后发优先） |

**取数优先级**：`tender/` 招标要求 > `profile.md` 事实信息 > skill 规范模板兜底 > 占位符（绝不杜撰）。

### 6.3 工作流程

1. **生成前先读 `bid-data/profile.md`**（存在则必须读；不存在按 [第二章](#二工作模式判定第-0-步) 初始化流程创建骨架）
2. **结构化信息直接填入**：公司全称、信用代码、资质编号、人员证书、业绩金额等写入对应章节
3. **扫描件按路径引用**：占位符带 `bid-data/company/...` 相对路径，文末汇总"待补充材料清单"
4. **资料缺失**：用 `【待补充：xxx】` 占位，不杜撰
5. **临期提醒**：资质证书、审计报告有效期 90 天内或已过期 → 交付时提醒
6. **多投标主体**：不同主体各自维护自己项目目录的 `bid-data/`；profile.md 第九节"投标主体"字段指明本项目主体

### 6.4 边界

- **只读引用**：skill 对 `bid-data/` 中用户资料只读；仅创建和写入 `output/`
- **隐私**：`company/08-签章素材/` 为敏感材料，仅在用户明确要求做电子签章版时引用，不复制到 `output/` 之外；标书中不写入与本项目无关的内部信息

## 七、写作硬性规则

1. **点对点应答**：技术参数、商务条款必须逐条引用原文并应答，禁止笼统的"完全响应"一句话带过（除非招标文件明确允许）
2. **不杜撰事实**：不编造资质等级、业绩合同、人员证书编号、财务数据、具体报价金额；需要时用占位符
3. **关键承诺与招标一致**：投标有效期、交货期/工期/服务期、质保期、付款方式等必须满足或优于招标要求；做不到的要明确提示用户
4. **措辞正式、肯定**：用"我方承诺""完全满足""优于"等肯定表述，避免"尽量""争取""可能"等模糊措辞
5. **不使用对手信息**：不写其他投标人名称，不做比较性贬低
6. **保密**：不在标书中写入与项目无关的投标方内部敏感信息
7. **中文规范**：简体中文，术语统一（如"投标方/投标人"全文统一，不混用"乙方"）

详细规范见 [references/writing-guidelines.md](references/writing-guidelines.md)。

## 八、输出检查清单

生成完成后，向用户交付时附以下确认项：

- [ ] 已说明工作模式（招标驱动 / 标准兜底 / 混合 / 初始化）
- [ ] 已扫描项目 `bid-data/`：`tender/` 招标文件、`profile.md` 资料索引
- [ ] `bid-data/profile.md` 已读取，公司信息/资质/人员/业绩已引用；缺失项用占位符并汇总到待补充清单
- [ ] 招标关键信息已与用户确认（模式 A）
- [ ] 目录与招标文件要求一致（模式 A）或符合行业标准（模式 B）
- [ ] 商务标、技术标、报价标三标齐全
- [ ] 输出已写入 `bid-data/output/<项目名>-投标文件/`
- [ ] 关键文书（投标函、授权委托书、偏离表、报价表）已生成
- [ ] 所有实质性要求/技术参数已逐条应答
- [ ] 负偏离/风险项已显式提示
- [ ] 待补充材料清单已汇总
- [ ] 占位符使用规范、可检索
- [ ] 签字盖章位置已标注
- [ ] 报价大小写与分项合计一致（报价部分）
- [ ] 已附自检结果
